# Compliance-Weighted Consensus — Reproducibility Pipeline

Code and data for the paper:

> **Compliance-Weighted Consensus: An IoT-Enhanced Hybrid Blockchain for Carbon-Compliant Fresh Food Supply Chains**
> Shadab Alam and Feisal Hadi Masmali, Jazan University, Saudi Arabia.
> Submitted to *Systems* (MDPI).

This repository reproduces every quantitative result, table, and figure in the
evaluation (Sections 6.4–6.6 and Appendix tables): the discrete-event simulation
of the artifact and its baselines, the Solidity contracts implementing
Algorithms 2 and 3, and the gas-measurement harness.

All experiments are seeded. Re-running the pipeline on the same package
versions reproduces `results/summary.json`, `results/gas.json`, and the figures
byte for byte.

## Requirements

- Python 3.10 or newer
- Node.js 18 or newer (for the Solidity compiler)

```bash
pip install -r requirements.txt
npm install            # solc 0.8.26
```

## Reproducing the paper

```bash
# 1. Contracts and gas costs  -> results/artifacts.json, results/gas.json (Table 7)
node scripts/compile.js
python scripts/measure_gas.py

# 2. All experiments, 30 seeds per configuration  -> results/summary.json
python sim/run_all.py                 # ~3-5 minutes

# 3. Response-model sensitivity       -> results/response_sweep.json (Table 10)
python sim/sweep_response.py

# 4. Figures
python sim/figure_architecture.py     # Figure 1
python sim/figures.py                 # Figures 2, 3, 4
python sim/figures_extra.py           # Figure 5
```

## Layout

```
contracts/
  EmissionTracker.sol    Algorithm 2: batch settlement, Eq. (8) penalty, Eq. (7) score decay.
                         Fixed-point exp via Pade(2,2) with range reduction (<0.2% error).
  CreditAuction.sol      Algorithm 3: Dutch auction, linear decay (Eq. (9)), reserve floor.

scripts/
  compile.js             Compiles both contracts with solc 0.8.26, optimizer on, 200 runs.
  measure_gas.py         Deploys to a local EVM (eth-tester / py-evm) and measures the
                         gas figures reported in Table 7.

sim/
  model.py               All models: SimPy bottleneck queues (leader, chain, ingestion),
                         latency stage composition, synchronization and partition model,
                         adaptive compliance agents (Eqs. (6)-(8)), Dutch-auction bidders,
                         ranking fidelity, injection defense, leader election.
                         Every parameter is declared in CONFIG and mirrors Table 2.
  run_all.py             Full experiment grid, 30 seeds per configuration; writes
                         results/summary.json with medians and interquartile ranges.
  sweep_response.py      Varies the behavioral response model for Table 10.
  figures.py             Figures 2, 3 and 4.
  figures_extra.py       Figure 5, from results/summary.json.
  figure_architecture.py Figure 1, the layered architecture diagram.

results/
  summary.json           All experiment outputs (medians, quartiles).
  gas.json               Measured gas costs (Table 7).
  response_sweep.json    Response-model sensitivity (Table 10).
  artifacts.json         Compiled contract ABIs and bytecode.

figures/
  fig1_architecture.png     -> manuscript Figure 1
  fig2_latency.png          -> manuscript Figure 2
  fig4_score.png            -> manuscript Figure 3  (block-proposal probability vs. score)
  fig3_auction.png          -> manuscript Figure 4  (Dutch-auction price trajectory)
  fig5_fidelity_lambda.png  -> manuscript Figure 5
```

Note the two middle filenames: `fig4_score.png` is manuscript Figure 3 and
`fig3_auction.png` is manuscript Figure 4. The filenames predate the final
figure ordering and are kept so the scripts and the archived outputs stay
consistent.

## Data

No external dataset is used. Every number in the paper is generated by the
simulation in this repository. The configuration that defines the device class,
consortium size, and workload is `CONFIG` in `sim/model.py`, which mirrors
Table 2 of the manuscript.
